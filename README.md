# BCM Switch Deployment Tool

Automated deployment of Cumulus switches to NVIDIA Base Command Manager (BCM) with cm-lite-daemon.

## Support note

This repository has been **tested on BCM 10.x only**. BCM 11.x support will come in a future iteration.

## Quick Start

```bash
python3 deploy_bcm_switches.py
```

That's it! The script will guide you through the entire process:
1. Prompt for switch IP addresses (supports ranges like `192.168.0.1-100`)
2. Ask for SSH credentials
3. Auto-detect the correct BCM network
4. Discover switch hostnames and MAC addresses
5. Add devices to BCM
6. Transfer and install cm-lite-daemon
7. Register devices with BCM

## Features

- **Interactive Configuration**: First-run wizard saves settings for future use
- **Flexible IP Input**: Supports multiple formats:
  - Single IPs: `192.168.0.1`
  - Ranges: `192.168.0.1-100` or `192.168.0.1-192.168.0.100`
  - Mixed: `192.168.0.1-10,192.168.2.1-10`
- **Auto-Discovery**: Automatically detects hostnames and MAC addresses from switches
- **Network Detection**: Matches switch IPs to BCM networks
- **Progress Tracking**: Resume interrupted deployments with `--resume`
- **Smart Caching**: Downloads dependencies once, reuses for all switches
- **Fully Airgapped Support**: Package everything for isolated networks

## Usage

### Normal Deployment

```bash
# Interactive mode (recommended for first run)
python3 deploy_bcm_switches.py

# Resume an interrupted deployment
python3 deploy_bcm_switches.py --resume

# Preview what would happen without making changes
python3 deploy_bcm_switches.py --dry-run
```

### How File Caching Works

The deployment script uses a "partially airgapped" approach by default:

1. **First run**: Downloads `cm-lite-daemon.zip` and pip packages to `.files/`
2. **All deployments**: Transfers cached files from BCM to switches via rsync
3. **Switches never need internet access** - they receive everything from BCM

This means you only need internet access on the BCM server for the initial download. Subsequent runs (including `--resume` and `--retry-failed`) reuse the cached files.

### Fully Airgapped Deployment

For BCM systems that have **no internet access at all**:

1. **On a system with internet access**, prepare the deployment package:
   ```bash
   python3 scripts/prep-airgapped.py
   ```

2. Transfer the generated `bcm-switches-deploy-airgapped-*.tar.gz` to your airgapped system

3. **On the airgapped system**:
   ```bash
   tar -xzf bcm-switches-deploy-airgapped-*.tar.gz
   cd bcm-switch-deploy
   python3 deploy_bcm_switches.py
   ```
   The script will detect the pre-packaged files in `.files/` and use them automatically.

## Configuration

Configuration is stored in `.configs/config.json` and includes:
- Switch IP addresses
- SSH username and password
- Selected BCM network
- VRF setting

### VRF names (what’s supported)

BCM/Cumulus VRFs are implemented as Linux VRF netdevices, so **VRF names follow Linux interface naming rules**:
- **No spaces**
- **Typically max 15 characters**
- Recommended characters: **letters, numbers, `_`, `-`, `.`**

If your environment uses a non-standard VRF name, that’s fine — the deploy flow will auto-detect it when possible, or prompt you to enter it.

On subsequent runs, you'll be asked whether to use existing configuration or update it.

## Prerequisites

### On the BCM Server

- Python 3.6+
- `sshpass` and `rsync` are expected to be present on BCM head nodes by default
- `cmsh` access (standard on BCM systems)
- Access to `/cm/shared/apps/cm-lite-daemon-dist/cm-lite-daemon.zip`

### On Target Switches

- SSH access with sudo privileges
- Network connectivity to BCM master
- Cumulus Linux (Debian-based)

## IP Address Format Examples

The script accepts IP addresses in various formats:

| Format | Example | Result |
|--------|---------|--------|
| Single IP | `192.168.0.1` | 1 IP |
| Last octet range | `192.168.0.1-10` | 10 IPs (192.168.0.1 to .10) |
| Full range | `192.168.0.1-192.168.0.100` | 100 IPs |
| Comma-separated | `192.168.0.1, 192.168.0.5` | 2 IPs |
| Mixed | `192.168.0.1-10,192.168.2.1-10` | 20 IPs |

## Troubleshooting

### "cmsh not found"

This script must run on a BCM head node where cmsh is available.

### "Cannot connect to switch"

- Verify the switch IP is correct and reachable (`ping <ip>`)
- Check SSH credentials are correct
- Ensure the switch allows SSH connections

### "Network detection failed"

If automatic network detection fails, you'll be prompted to select from available BCM networks manually.

### Resuming a failed deployment

If deployment fails partway through:
```bash
python3 deploy_bcm_switches.py --resume
```

This continues from the last successful step.

## Output Files
