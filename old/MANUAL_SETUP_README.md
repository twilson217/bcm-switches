# Manual Cumulus Device Setup for BCM Management

This guide provides step-by-step instructions for manually adding Cumulus devices to BCM (Base Command Manager) with cm-lite-daemon management. This is the manual equivalent of the automated `complete_cumulus_setup.py` script.

## Overview

The complete setup process involves three main phases:
1. **Adding devices to BCM** - Register device information in BCM
2. **Transferring cm-lite-daemon** - Copy daemon files to each device
3. **Installing and registering** - Install daemon, configure it, and register with BCM

## Prerequisites

### Required Information
For each device, you'll need:
- **Hostname**: Device hostname (e.g., `spine01`, `leaf02`)
- **IP Address**: Management IP address
- **MAC Address**: Management interface MAC address
- **Network/Role**: Device network or role designation

### Required Access
- **BCM System Access**: Access to BCM master node with `cmsh` command
- **Device SSH Access**: SSH access to Cumulus devices (username/password or SSH key)
- **Network Connectivity**: Devices must be reachable from BCM master

### Required Files
- `cm-lite-daemon` binary and related files
- Bootstrap certificates (generated by BCM)

## Phase 1: Adding Devices to BCM

### Step 1.1: Access BCM Command Shell

```bash
# Connect to BCM master node and start cmsh
cmsh
```

### Step 1.2: Navigate to Device Management

```bash
# In cmsh
device
```

### Step 1.3: Add Each Device

For each Cumulus device, execute the following commands in `cmsh`:

```bash
# Add a new device (replace values as needed)
add <hostname> ip=<ip_address> mac=<mac_address> network=<network_name>

# Example:
add spine01 ip=10.141.1.1 mac=44:38:39:00:01:01 network=internalnet
add leaf01 ip=10.141.1.10 mac=44:38:39:00:01:10 network=internalnet
```

### Step 1.4: Commit Changes

```bash
# Commit the device additions
commit
```

### Step 1.5: Verify Device Addition

```bash
# List devices to verify they were added
list
```

### Step 1.6: Exit cmsh

```bash
# Exit cmsh
quit
```

### Step 1.7: Wait for Bootstrap Certificate Generation

After adding devices, BCM will begin generating bootstrap certificates. Wait approximately 15-30 seconds before proceeding to ensure the process has started.

## Phase 2: Transferring cm-lite-daemon to Devices

### Step 2.1: Prepare Daemon Files

Ensure you have the cm-lite-daemon files ready for transfer:
- `cm-lite-daemon` binary
- Configuration files
- Any required libraries

### Step 2.2: Check Device Connectivity

Before transferring files, verify each device is reachable:

```bash
# Test connectivity to each device
ping -c 3 <device_ip>

# Example:
ping -c 3 10.141.1.1
```

### Step 2.3: Transfer Files to Each Device

Use `scp` or `rsync` to transfer daemon files to each device:

```bash
# Using SCP (replace paths and credentials as needed)
scp -r /path/to/cm-lite-daemon cumulus@<device_ip>:/tmp/

# Using rsync (alternative method)
rsync -av /path/to/cm-lite-daemon cumulus@<device_ip>:/tmp/

# Example:
scp -r /opt/cm-lite-daemon cumulus@10.141.1.1:/tmp/
```

If using SSH keys:
```bash
scp -i /path/to/ssh_key -r /path/to/cm-lite-daemon cumulus@<device_ip>:/tmp/
```

### Step 2.4: Verify File Transfer

SSH to each device and verify files were transferred correctly:

```bash
# SSH to device
ssh cumulus@<device_ip>

# Check transferred files
ls -la /tmp/cm-lite-daemon/

# Exit device
exit
```

## Phase 3: Installing and Registering Devices

Perform the following steps for each device:

### Step 3.1: SSH to Device

```bash
ssh cumulus@<device_ip>
```

### Step 3.2: Prepare Installation Directory

```bash
# Create installation directory (if it doesn't exist)
sudo mkdir -p /opt/cm-lite-daemon

# Move files from temporary location
sudo mv /tmp/cm-lite-daemon/* /opt/cm-lite-daemon/

# Set proper permissions
sudo chown -R root:root /opt/cm-lite-daemon
sudo chmod +x /opt/cm-lite-daemon/cm-lite-daemon
```

### Step 3.3: Get BCM Master IP

Determine the BCM master IP address (if not already known):

```bash
# On BCM master node, run:
cmsh -c "device; use master; get ip"
```

### Step 3.4: Transfer Bootstrap Certificates

Copy bootstrap certificates from BCM master to the device:

```bash
# On BCM master, find and copy bootstrap certificates
# (This step varies depending on BCM configuration)
# Typically located in /opt/bcm/certificates/ or similar

# Copy to device (run from BCM master)
scp /path/to/bootstrap/certs/* cumulus@<device_ip>:/opt/cm-lite-daemon/certs/
```

### Step 3.5: Configure cm-lite-daemon

Create or update the daemon configuration file:

```bash
# On the device, create/edit configuration
sudo nano /opt/cm-lite-daemon/config.yaml
```

Configuration example:
```yaml
bcm_master:
  ip: <bcm_master_ip>
  hostname: master
  port: 8443

device:
  hostname: <device_hostname>
  vrf: mgmt

certificates:
  path: /opt/cm-lite-daemon/certs/
  
logging:
  level: info
  file: /var/log/cm-lite-daemon.log
```

### Step 3.6: Create Systemd Service (Optional)

Create a systemd service for automatic startup:

```bash
# Create service file
sudo nano /etc/systemd/system/cm-lite-daemon.service
```

Service file content:
```ini
[Unit]
Description=CM Lite Daemon
After=network.target

[Service]
Type=simple
User=root
ExecStart=/opt/cm-lite-daemon/cm-lite-daemon --config /opt/cm-lite-daemon/config.yaml
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

### Step 3.7: Start cm-lite-daemon

```bash
# Reload systemd if service was created
sudo systemctl daemon-reload

# Start the daemon (using systemd)
sudo systemctl start cm-lite-daemon
sudo systemctl enable cm-lite-daemon

# Or start manually
sudo /opt/cm-lite-daemon/cm-lite-daemon --config /opt/cm-lite-daemon/config.yaml &
```

### Step 3.8: Verify Installation

```bash
# Check daemon status
sudo systemctl status cm-lite-daemon

# Check daemon logs
sudo journalctl -u cm-lite-daemon -f

# Or check manual logs
tail -f /var/log/cm-lite-daemon.log
```

### Step 3.9: Verify BCM Registration

```bash
# On BCM master, check if device appears
cmsh -c "device; show"

# Look for your device in the list
```

## Verification and Troubleshooting

### Overall Verification Steps

1. **Check BCM Device List**:
   ```bash
   # On BCM master
   cmsh -c "device; show"
   ```

2. **Verify Daemon Status on All Devices**:
   ```bash
   # On each device
   sudo systemctl status cm-lite-daemon
   ```

3. **Check Network Connectivity**:
   ```bash
   # From devices to BCM master
   ping -c 3 <bcm_master_ip>
   
   # Test specific port connectivity
   telnet <bcm_master_ip> 8443
   ```

### Common Issues and Solutions

#### Device Not Appearing in BCM
- **Cause**: Bootstrap certificates not transferred or incorrect
- **Solution**: Re-transfer certificates and restart daemon

#### Connection Refused Errors
- **Cause**: Firewall blocking connection or wrong port
- **Solution**: Check firewall rules and BCM master port configuration

#### Authentication Failures
- **Cause**: Invalid certificates or configuration mismatch
- **Solution**: Regenerate certificates and verify configuration

#### VRF Issues
- **Cause**: Daemon trying to connect through wrong VRF
- **Solution**: Verify VRF configuration matches network setup

### Log Analysis

**BCM Master Logs**:
```bash
# Check BCM logs for device registration
tail -f /var/log/bcm/device-manager.log
```

**Device Daemon Logs**:
```bash
# Check daemon logs on devices
sudo journalctl -u cm-lite-daemon -f
tail -f /var/log/cm-lite-daemon.log
```

## Advanced Configuration

### Custom Installation Directory

If installing to a directory other than `/opt`:

1. Update all file paths in commands above
2. Ensure proper permissions on custom directory
3. Update systemd service file paths if using systemd

### Multiple BCM Masters

For environments with multiple BCM masters:

1. Update configuration with correct master IP
2. Ensure certificates are from correct master
3. Verify network routing to chosen master

### Security Considerations

1. **SSH Key Authentication**: Use SSH keys instead of passwords when possible
2. **Certificate Management**: Regularly rotate certificates as per security policy
3. **Firewall Rules**: Ensure only necessary ports are open
4. **User Permissions**: Use least privilege principle for service accounts
